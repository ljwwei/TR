系統架構、準點標準與 TDX 串接說明

1. 為什麼多人瀏覽不會增加 TDX API 讀取次數？

本專案將資料「採集」與「瀏覽」完全解耦：由 Cloudflare Worker 準點排程（日間 05:00–23:45 每 15 分鐘、深夜 00:00–04:30 每 30 分鐘，貼合 TDX 10–15 分鐘電子看板視窗並涵蓋跨夜班次）觸發 GitHub Actions 呼叫 TDX v3 StationLiveBoard API，去重彙整為單日／單月／單年靜態 JSON 檔存入 tdx-data 分支並部署至 GitHub Pages。所有訪客僅從 CDN 讀取靜態檔，對 TDX 的額外消耗永遠為 0。

2. 基礎會員（免費 3 點／月）額度估算

  • 日間每 15 分鐘 ＋ 深夜每 30 分鐘：每日 86 次 × 30 天 = 2,580 次／月（呼叫約 1.72 點）。
  • 依實測單次壓縮封包約 55 KB 計算，全臺 245 站每月流量約 135–145 MB（約 0.90–0.96 點）；合計約 2.6 – 2.7 點／月，內建 2.75 點 自動熔斷保護，剛好貼合基礎會員免費 3 點額度。
  • 若為 TDX 付費銅級以上會員，可於 wrangler.toml 將排程調高至每 5–10 分鐘一次並放寬 MAX_MONTHLY_POINTS。

3. 兩種準點標準說明

  • 臺鐵官方標準（≤ 5 分鐘）：延誤 5 分鐘（含）以內即計為準點，與官方公告統計口徑一致。
  • 嚴格準點（0 分鐘）：僅 DelayTime = 0 視為準點，更貼近尖峰通勤族轉乘體感。

4. 如何啟用您自己的 TDX 即時資料？

  1. 至 GitHub 專案的 Settings → Secrets and variables → Actions 新增 TDX_CLIENT_ID 與 TDX_CLIENT_SECRET。
  2. 在 Settings → Pages 將 Source 設為 GitHub Actions。
  3. 至 Actions → Collect TDX TRA Punctuality Data 手動點選 Run workflow，約 1 分鐘後本站即自動切換為真實即時累積數據！
